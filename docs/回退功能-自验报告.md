# 回退功能 - 自验报告

## 1. 自验范围

- 后端：`message:rewind` 事件接入、异步执行、回滚补偿、数据一致性更新。
- 前端：用户消息长按/右键浮层、点击“回溯消息”后即时移除。
- 文档：WebSocket 事件说明更新。

## 2. 自动化验证

### 2.1 后端单测

执行命令：

```bash
npm test -- chat.service.spec.ts chat.gateway.spec.ts
```

结果：
- Test Suites: 2 passed, 2 total
- Tests: 15 passed, 15 total

覆盖点：
- `ChatService.rewindFromMessage` 删除锚点及后续消息；
- transcript 过滤写回；
- shared memory 清理触发；
- `ChatGateway.handleRewind` 接受请求并触发异步回溯。

## 3. 手工场景验证建议

1. 发送多轮 user/assistant 消息；
2. 长按（或右键）某条 user 消息，点击“回溯消息”；
3. 观察前端：该消息及后续消息立即消失；
4. 观察后端日志：`rewind requested` -> `rewind completed`；
5. 断开重连后检查 `chat:history`，确认不会回流已删除消息。

## 4. 结果结论

- 需求功能已实现：
  - 前端局部回退交互；
  - 后端异步回退与一致性收敛（PG/Redis/transcript）；
  - 回退失败补偿恢复；
  - 事件文档同步。

## 5. 已知注意项

- 当前时序语义基于 `createdAt + id` 排序，不引入新顺序字段；
- 前端离线时执行本地回退后不会立即同步后端（需连接恢复后再发或重连拉取）。
