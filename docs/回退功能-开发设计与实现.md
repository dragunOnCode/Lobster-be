# 回退功能 - 开发设计与实现

## 1. 目标

实现“对话消息回溯”：

- 用户选择一条 `role=user` 的消息作为锚点；
- 删除该消息及其后的消息；
- 前端即时移除展示；
- 后端异步完成持久层一致删除（PostgreSQL / Redis / transcript.jsonl）；
- 保留关键日志，失败可定位。

## 2. 设计决策

### 2.1 删除边界（如何判断“某条消息以后”）

采用“业务侧按时间顺序切片”方案：

1. 先加载会话全量消息并按 `createdAt ASC, id ASC` 排序；
2. 以 `messageId` 找到锚点索引；
3. `kept = [0, anchorIndex)`，`removed = [anchorIndex, end)`；
4. 对 `kept` 做全量重建写回（而不是做多存储的部分删除）。

原因：

- 现有 `messages` 表并未定义业务顺序字段；
- 复用 `createdAt` 可快速落地；
- 通过“全量替换”可保证 DB / Redis / 向量索引收敛一致。

### 2.2 原子性策略

跨 PG/Redis/File 严格分布式事务不可行，采用“补偿事务（Saga）”保证效果上的原子性：

1. 先做快照：`fullSessionMessages` + `transcriptSnapshot`；
2. 执行写入：
  - `replaceSessionMessages(sessionId, kept)`（包含 DB + Redis + 向量重建）
  - 清理 shared memory
  - `replaceTranscript(sessionId, filteredTranscript)`
3. 任一步失败：执行补偿恢复：
  - `replaceSessionMessages(sessionId, fullSessionMessages)`
  - `replaceTranscript(sessionId, transcriptSnapshot)`

### 2.3 前端交互

- 仅对 `message.role === 'user'` 的消息生效；
- 支持长按（移动端）和右键（桌面端）打开“回溯消息”浮层；
- 点击浮层外部自动关闭；
- 点击“回溯消息”后，前端先本地删除该消息及后续消息，再发起 `message:rewind`。

## 3. 事件流

1. FE 发 `message:rewind({ sessionId, messageId })`；
2. BE 立即回 `message:rewind:accepted`；
3. BE 异步执行回溯；
4. 成功后广播：
  - `chat:history`（最新历史）
  - `message:rewind:done`
5. 失败后广播：`message:rewind:error`。

## 5. 日志与可观测性

后端新增关键日志：

- 收到请求：session/message/user；
- 回溯成功：removedCount；
- 回溯失败与补偿恢复状态。

## 6. 边界与限制

- 仅允许从 `user` 消息回溯；
- 依赖 `createdAt` 作为时序主键，若极端同毫秒并发，用 `id` 做次级排序；
- 若后端离线，前端仍先做本地回退，连接恢复后需重新同步历史。
