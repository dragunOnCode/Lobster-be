# 需求

当前系统的后端是多Agent协作的聊天室，我希望Agent完成实际的编码工作。现在我需要你根据我以下的考虑，输出针对多个Agent协作的设计：

# 考虑点

1. agent需要在工作区输出代码，当前用户交互的地方是web前端，**claude code/codex cli/gemini cli**工具在当前会话的 workspace/ 编辑完代码后，是否要通过打包的方式返回给用户在前端下载？
2. 本系统是Multi Agent协作系统，希望用户尽可能方便地完成需求。比如用户只要提供一个需求：@Claude 实现一个贪吃蛇游戏。系统就根据mention调用claude，而claude提前规划方案，再输出第一版代码，在答复的消息中@Codex进行code review。让每个Agent在自己这一轮工作中完成"思考->规划步骤->工作->评估->再工作...->再评估..."，且能感知到会话内其他agent并交接下一棒。我理解这需要在prompt以及workflow都下功夫。
3. agent之间存在A2A的工作接力，考虑到后续可能将后端做成分布式服务，需要考虑如何处理不同机器上cli的协作。比如，机器A上claude code完成功能1，可能调度到机器B上的codex继续完成功能2，然而，由于功能1在机器A的工作区实现，机器B的工作区根本看不见修改。
4. 我希望每个cli在完成任务的时候更具条理，比如我@Claude完成一个需求，我希望系统利用CoT来展示Agent的思考过程，同时便于追溯（思考过程应该单独成表，关联具体message）。
5. 我希望在当前使用LangGraph的情况下，结合业界先进实践，用**ReAct/Plan-And-Execute**或是其他Agent的思考范式完善这块使用LangGraph的Agent编排代码。
6. 当前并没有手动实现Agent的功能，而是使用各大厂商的命令行工具(claude code/codex/gemini cli)，这些工具本身已经实现了Agent的能力，诸如MCP/Skills等等。帮我构思一下我们的系统如何在cli工具的强大能力基础上，对这些机制(MCP/Skills等)做增强。



# 目标

结合我在上面提的内容，帮我输出一份针对每个考虑点的设计，完善多Agent协作功能。要求包括以下几个维度：

1. **看现状**：该点在当前项目的能力已经实现到什么程度；
2. **看业界**：关于该考虑点，业界有没有什么有含金量的实现案例可供借鉴；
3. **思考过程**：针对该考虑点，网上的信息有什么启发？面对不同案例你是如何抉择的？各种性能、可靠性、功能指标的取舍标准是什么？理清楚你的思考脉络，方便项目成员跟上你的思维；
4. **给方法**：针对该考虑点，如何在项目内落地？有没有可供衡量的多个方案？给出方案设计；
