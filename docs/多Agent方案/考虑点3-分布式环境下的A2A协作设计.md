## 看现状

### 当前实现程度

根据项目探索，当前系统的分布式能力：

**已实现：**
- ✅ **单机多Agent协作**：所有Agent在同一进程中运行
- ✅ **工作区隔离**：每个会话有独立的文件系统目录
- ✅ **PostgreSQL共享状态**：消息、会话数据存储在数据库
- ✅ **Redis消息队列**：使用BullMQ处理异步任务
- ✅ **WebSocket实时通信**：前端与后端的实时连接

**当前缺失：**
- ❌ **跨机器工作区同步**：机器A的工作区无法被机器B访问
- ❌ **分布式任务调度**：无法将任务调度到不同机器的Agent
- ❌ **工作区状态一致性**：没有分布式文件系统或同步机制
- ❌ **Agent负载均衡**：无法根据负载动态分配任务
- ❌ **故障转移**：Agent失败后无法自动切换到其他实例

### 核心问题

**问题场景：**
```
用户请求 → 机器A (Claude Agent)
              ↓
         创建文件: workspace/session-123/code/index.html
              ↓
         握手转移 → 机器B (Codex Agent)
              ↓
         ❌ 无法访问 workspace/session-123/
         ❌ 看不到 index.html
         ❌ 无法进行代码审查
```

## 看业界

### 业界实践案例

#### 1. **Kubernetes + Shared Volume**

**方案：**
- 使用PersistentVolume (PV) 作为共享存储
- 所有Pod挂载同一个Volume
- 支持ReadWriteMany (RWX) 模式

**优势：**
- 简单直接，文件系统语义完整
- 无需修改应用代码
- 支持大文件和复杂目录结构

**劣势：**
- 需要NFS/CephFS等分布式文件系统
- 性能瓶颈（网络IO）
- 单点故障风险（存储节点）

**适用场景：**
- 文件数量少、变更频率低
- 对一致性要求高
- 已有K8s基础设施

#### 2. **Object Storage (S3/MinIO)**

**方案：**
- 工作区文件存储在对象存储
- Agent执行前下载，执行后上传
- 使用版本控制和ETag防冲突

**优势：**
- 高可用、高扩展性
- 成本低（按需付费）
- 天然支持版本管理

**劣势：**
- 不支持文件系统语义（无目录、无追加写）
- 上传/下载开销大
- 需要修改CLI工具的文件访问方式

**适用场景：**
- 云原生架构
- 文件以整体为单位操作
- 对延迟不敏感

#### 3. **Git + Remote Repository**

**方案：**
- 每个工作区是一个Git仓库
- Agent执行前git pull，执行后git push
- 使用分支隔离不同Agent的工作

**优势：**
- 天然的版本控制和冲突解决
- 可追溯所有变更历史
- 支持离线工作

**劣势：**
- Git操作开销大（大文件、频繁提交）
- 需要处理合并冲突
- 不适合二进制文件

**适用场景：**
- 代码文件为主
- 需要完整的变更历史
- 团队协作场景

#### 4. **Distributed Cache (Redis/Hazelcast)**

**方案：**
- 工作区文件存储在分布式缓存
- 使用Hash结构：`workspace:{sessionId}:{filePath} -> content`
- 支持发布/订阅通知文件变更

**优势：**
- 低延迟（内存访问）
- 支持实时同步
- 简单的API

**劣势：**
- 内存成本高
- 不适合大文件
- 数据持久化需要额外配置

**适用场景：**
- 小文件、高频访问
- 需要实时同步
- 临时工作区

#### 5. **Event Sourcing + CQRS**

**方案：**
- 不存储文件内容，只存储操作事件
- 事件：`FileCreated`, `FileModified`, `FileDeleted`
- 每个Agent重放事件重建工作区状态

**优势：**
- 完整的操作历史
- 支持时间旅行（回溯到任意时刻）
- 易于实现分布式一致性

**劣势：**
- 实现复杂度高
- 重放事件开销大
- 需要快照机制优化性能

**适用场景：**
- 需要完整审计日志
- 复杂的协作场景
- 对一致性要求极高

## 思考过程

### 信息启发

从业界案例可以看出，分布式工作区同步的核心矛盾是：

**性能 vs 一致性 vs 复杂度**

| 方案 | 性能 | 一致性 | 复杂度 | 成本 |
|------|------|--------|--------|------|
| Shared Volume | ⚠️ 中 | ✅ 强 | ✅ 低 | ⚠️ 中 |
| Object Storage | ❌ 低 | ⚠️ 最终 | ⚠️ 中 | ✅ 低 |
| Git Repository | ❌ 低 | ✅ 强 | ⚠️ 中 | ✅ 低 |
| Distributed Cache | ✅ 高 | ⚠️ 最终 | ✅ 低 | ❌ 高 |
| Event Sourcing | ⚠️ 中 | ✅ 强 | ❌ 高 | ⚠️ 中 |

### 我们的场景特点

1. **文件特征**：
   - 以代码文件为主（文本文件）
   - 文件数量：10-100个/会话
   - 文件大小：通常 < 100KB
   - 变更频率：每个Agent任务产生1-10次变更

2. **一致性要求**：
   - Agent必须看到前一个Agent的所有变更
   - 不允许丢失变更
   - 可以容忍短暂延迟（秒级）

3. **性能要求**：
   - Agent启动延迟 < 5秒
   - 文件同步延迟 < 2秒
   - 支持并发：10+ Agent同时工作

4. **成本约束**：
   - 优先使用现有基础设施（PostgreSQL, Redis）
   - 避免引入新的存储系统
   - 可以接受适度的存储成本

### 方案抉择

**排除方案：**
- ❌ **Shared Volume**：需要K8s和分布式文件系统，基础设施成本高
- ❌ **Git Repository**：Git操作开销大，不适合高频变更
- ❌ **Event Sourcing**：实现复杂度过高，投入产出比低

**候选方案：**
- ✅ **Object Storage (MinIO)**：成熟、可靠、成本可控
- ✅ **Distributed Cache (Redis)**：已有Redis，增量成本低
- ✅ **混合方案**：Redis缓存 + PostgreSQL持久化 + MinIO归档

### 取舍标准

1. **渐进式实现**：先实现基础功能，再优化性能
2. **复用现有基础设施**：优先使用PostgreSQL和Redis
3. **可观测性**：所有同步操作可追踪、可回溯
4. **故障恢复**：支持从任意时刻恢复工作区状态

### 最终选择

**混合方案：三层存储架构**

```
┌─────────────────────────────────────────────────────────┐
│ Layer 1: Redis (热数据缓存)                              │
│  - 存储最近访问的文件内容                                 │
│  - TTL: 1小时                                            │
│  - 用途：快速读取、实时同步通知                           │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 2: PostgreSQL (元数据 + 小文件)                    │
│  - 存储文件元数据（路径、大小、哈希、版本）                │
│  - 存储小文件内容 (< 1MB)                                │
│  - 用途：持久化、版本管理、查询                           │
└─────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────┐
│ Layer 3: MinIO (大文件归档)                              │
│  - 存储大文件 (>= 1MB)                                   │
│  - 存储工作区快照（ZIP）                                  │
│  - 用途：长期归档、下载导出                               │
└─────────────────────────────────────────────────────────┘
```

**理由：**
- Redis提供低延迟访问和实时通知
- PostgreSQL提供强一致性和事务支持
- MinIO提供低成本的大文件存储
- 三层架构平衡了性能、一致性和成本

#### 数据库设计

**新增表1：workspace_files**

```sql
CREATE TABLE workspace_files (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  file_path TEXT NOT NULL, -- 相对路径，如 "src/index.html"
  content_hash VARCHAR(64) NOT NULL, -- SHA-256哈希
  file_size BIGINT NOT NULL,
  mime_type VARCHAR(100),

  -- 内容存储策略
  storage_type VARCHAR(20) NOT NULL, -- 'inline' | 'minio'
  content TEXT, -- storage_type='inline'时存储内容
  minio_key TEXT, -- storage_type='minio'时存储对象键

  -- 版本信息
  version INT NOT NULL DEFAULT 1,
  created_by VARCHAR(50), -- agent_id
  created_at TIMESTAMP DEFAULT NOW(),
  updated_at TIMESTAMP DEFAULT NOW(),
  deleted_at TIMESTAMP, -- 软删除

  -- 元数据
  metadata JSONB,

  UNIQUE(session_id, file_path, version)
);

CREATE INDEX idx_workspace_files_session ON workspace_files(session_id, deleted_at);
CREATE INDEX idx_workspace_files_path ON workspace_files(session_id, file_path, version DESC);
CREATE INDEX idx_workspace_files_hash ON workspace_files(content_hash);
```

**新增表2：workspace_sync_events**

```sql
CREATE TABLE workspace_sync_events (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id UUID NOT NULL REFERENCES sessions(id) ON DELETE CASCADE,
  event_type VARCHAR(20) NOT NULL, -- 'file_created' | 'file_updated' | 'file_deleted'
  file_path TEXT NOT NULL,
  file_id UUID REFERENCES workspace_files(id),

  -- 事件来源
  source_agent_id VARCHAR(50),
  source_machine_id VARCHAR(100), -- 机器标识

  -- 事件内容
  before_hash VARCHAR(64), -- 变更前的哈希
  after_hash VARCHAR(64), -- 变更后的哈希
  diff TEXT, -- 文件diff（可选）

  -- 时间戳
  created_at TIMESTAMP DEFAULT NOW(),

  -- 元数据
  metadata JSONB
);

CREATE INDEX idx_workspace_sync_events_session ON workspace_sync_events(session_id, created_at DESC);
CREATE INDEX idx_workspace_sync_events_file ON workspace_sync_events(file_path, session_id);
```

#### 核心服务实现

**WorkspaceSyncService**

```typescript
// src/workspace/services/workspace-sync.service.ts

import { Injectable } from '@nestjs/common';
import { InjectRepository } from '@nestjs/typeorm';
import { Repository } from 'typeorm';
import { Redis } from 'ioredis';
import { MinioService } from './minio.service';
import * as crypto from 'crypto';
import * as fs from 'fs/promises';
import * as path from 'path';

@Injectable()
export class WorkspaceSyncService {
  private readonly REDIS_CACHE_PREFIX = 'workspace:file:';
  private readonly REDIS_PUBSUB_CHANNEL = 'workspace:changes';
  private readonly INLINE_SIZE_LIMIT = 1024 * 1024; // 1MB

  constructor(
    @InjectRepository(WorkspaceFile)
    private readonly fileRepo: Repository<WorkspaceFile>,
    @InjectRepository(WorkspaceSyncEvent)
    private readonly eventRepo: Repository<WorkspaceSyncEvent>,
    private readonly redis: Redis,
    private readonly minio: MinioService
  ) {
    // 订阅Redis Pub/Sub
    this.subscribeToChanges();
  }

  /**
   * 下载整个工作区到本地目录
   */
  async downloadWorkspace(
    sessionId: string,
    targetDir: string
  ): Promise<void> {
    // 1. 获取所有文件列表
    const files = await this.fileRepo.find({
      where: {
        sessionId,
        deletedAt: null
      },
      order: {
        version: 'DESC'
      }
    });

    // 2. 去重（保留最新版本）
    const latestFiles = new Map<string, WorkspaceFile>();
    for (const file of files) {
      if (!latestFiles.has(file.filePath)) {
        latestFiles.set(file.filePath, file);
      }
    }

    // 3. 并行下载所有文件
    await Promise.all(
      Array.from(latestFiles.values()).map(async (file) => {
        const content = await this.getFileContent(file);
        const fullPath = path.join(targetDir, file.filePath);

        // 确保目录存在
        await fs.mkdir(path.dirname(fullPath), { recursive: true });

        // 写入文件
        await fs.writeFile(fullPath, content);
      })
    );
  }

  /**
   * 上传工作区变更
   */
  async uploadChanges(
    sessionId: string,
    sourceDir: string,
    agentId: string,
    machineId: string
  ): Promise<void> {
    // 1. 扫描本地目录
    const localFiles = await this.scanDirectory(sourceDir);

    // 2. 获取远程文件列表
    const remoteFiles = await this.getFileList(sessionId);

    // 3. 计算差异
    const changes = await this.computeDiff(localFiles, remoteFiles);

    // 4. 上传变更
    for (const change of changes) {
      switch (change.type) {
        case 'created':
        case 'updated':
          await this.uploadFile(
            sessionId,
            change.filePath,
            change.content,
            agentId,
            machineId
          );
          break;
        case 'deleted':
          await this.deleteFile(
            sessionId,
            change.filePath,
            agentId,
            machineId
          );
          break;
      }
    }
  }

  /**
   * 上传单个文件
   */
  private async uploadFile(
    sessionId: string,
    filePath: string,
    content: Buffer,
    agentId: string,
    machineId: string
  ): Promise<WorkspaceFile> {
    // 1. 计算哈希
    const hash = crypto.createHash('sha256').update(content).digest('hex');

    // 2. 检查是否已存在相同内容
    const existing = await this.fileRepo.findOne({
      where: {
        sessionId,
        filePath,
        contentHash: hash,
        deletedAt: null
      }
    });

    if (existing) {
      return existing; // 内容未变更，跳过
    }

    // 3. 确定存储策略
    const fileSize = content.length;
    const storageType = fileSize < this.INLINE_SIZE_LIMIT ? 'inline' : 'minio';

    let minioKey: string | null = null;
    let inlineContent: string | null = null;

    if (storageType === 'inline') {
      inlineContent = content.toString('utf-8');
    } else {
      // 上传到MinIO
      minioKey = `workspaces/${sessionId}/${hash}`;
      await this.minio.putObject(minioKey, content);
    }

    // 4. 获取当前版本号
    const latestVersion = await this.fileRepo
      .createQueryBuilder('file')
      .where('file.session_id = :sessionId', { sessionId })
      .andWhere('file.file_path = :filePath', { filePath })
      .orderBy('file.version', 'DESC')
      .getOne();

    const newVersion = latestVersion ? latestVersion.version + 1 : 1;

    // 5. 保存到数据库
    const file = await this.fileRepo.save({
      sessionId,
      filePath,
      contentHash: hash,
      fileSize,
      mimeType: this.detectMimeType(filePath),
      storageType,
      content: inlineContent,
      minioKey,
      version: newVersion,
      createdBy: agentId
    });

    // 6. 发布变更事件
    await this.publishChangeEvent({
      sessionId,
      eventType: latestVersion ? 'file_updated' : 'file_created',
      filePath,
      fileId: file.id,
      sourceAgentId: agentId,
      sourceMachineId: machineId,
      beforeHash: latestVersion?.contentHash,
      afterHash: hash
    });

    // 7. 更新Redis缓存
    await this.updateCache(sessionId, filePath, content);

    return file;
  }

  /**
   * 获取文件内容（三层查找）
   */
  private async getFileContent(file: WorkspaceFile): Promise<Buffer> {
    // Layer 1: Redis缓存
    const cacheKey = `${this.REDIS_CACHE_PREFIX}${file.sessionId}:${file.filePath}`;
    const cached = await this.redis.getBuffer(cacheKey);
    if (cached) {
      return cached;
    }

    // Layer 2: PostgreSQL inline
    if (file.storageType === 'inline' && file.content) {
      const buffer = Buffer.from(file.content, 'utf-8');
      await this.updateCache(file.sessionId, file.filePath, buffer);
      return buffer;
    }

    // Layer 3: MinIO
    if (file.storageType === 'minio' && file.minioKey) {
      const buffer = await this.minio.getObject(file.minioKey);
      await this.updateCache(file.sessionId, file.filePath, buffer);
      return buffer;
    }

    throw new Error(`Cannot retrieve content for file: ${file.filePath}`);
  }

  /**
   * 更新Redis缓存
   */
  private async updateCache(
    sessionId: string,
    filePath: string,
    content: Buffer
  ): Promise<void> {
    const cacheKey = `${this.REDIS_CACHE_PREFIX}${sessionId}:${filePath}`;
    await this.redis.setex(cacheKey, 3600, content); // TTL: 1小时
  }

  /**
   * 发布变更事件
   */
  private async publishChangeEvent(event: Partial<WorkspaceSyncEvent>): Promise<void> {
    // 1. 保存到数据库
    await this.eventRepo.save(event);

    // 2. 发布到Redis Pub/Sub
    await this.redis.publish(
      `${this.REDIS_PUBSUB_CHANNEL}:${event.sessionId}`,
      JSON.stringify(event)
    );
  }

  /**
   * 订阅变更事件
   */
  private subscribeToChanges(): void {
    const subscriber = this.redis.duplicate();

    subscriber.psubscribe(`${this.REDIS_PUBSUB_CHANNEL}:*`, (err, count) => {
      if (err) {
        console.error('Failed to subscribe:', err);
      }
    });

    subscriber.on('pmessage', async (pattern, channel, message) => {
      const event = JSON.parse(message) as WorkspaceSyncEvent;

      // 清除本地缓存，强制重新加载
      const cacheKey = `${this.REDIS_CACHE_PREFIX}${event.sessionId}:${event.filePath}`;
      await this.redis.del(cacheKey);

      console.log(`Workspace change detected: ${event.eventType} ${event.filePath}`);
    });
  }

  /**
   * 扫描本地目录
   */
  private async scanDirectory(dir: string): Promise<Map<string, Buffer>> {
    const files = new Map<string, Buffer>();

    async function scan(currentDir: string, relativePath: string = '') {
      const entries = await fs.readdir(currentDir, { withFileTypes: true });

      for (const entry of entries) {
        const fullPath = path.join(currentDir, entry.name);
        const relPath = path.join(relativePath, entry.name);

        if (entry.isDirectory()) {
          await scan(fullPath, relPath);
        } else if (entry.isFile()) {
          const content = await fs.readFile(fullPath);
          files.set(relPath, content);
        }
      }
    }

    await scan(dir);
    return files;
  }

  /**
   * 计算文件差异
   */
  private async computeDiff(
    localFiles: Map<string, Buffer>,
    remoteFiles: Map<string, WorkspaceFile>
  ): Promise<FileChange[]> {
    const changes: FileChange[] = [];

    // 检查新增和修改
    for (const [filePath, content] of localFiles) {
      const hash = crypto.createHash('sha256').update(content).digest('hex');
      const remote = remoteFiles.get(filePath);

      if (!remote) {
        changes.push({ type: 'created', filePath, content });
      } else if (remote.contentHash !== hash) {
        changes.push({ type: 'updated', filePath, content });
      }
    }

    // 检查删除
    for (const [filePath, remote] of remoteFiles) {
      if (!localFiles.has(filePath)) {
        changes.push({ type: 'deleted', filePath });
      }
    }

    return changes;
  }

  private detectMimeType(filePath: string): string {
    const ext = path.extname(filePath).toLowerCase();
    const mimeTypes: Record<string, string> = {
      '.js': 'application/javascript',
      '.ts': 'application/typescript',
      '.html': 'text/html',
      '.css': 'text/css',
      '.json': 'application/json',
      '.md': 'text/markdown',
      '.txt': 'text/plain'
    };
    return mimeTypes[ext] || 'application/octet-stream';
  }
}
```

```typescript
// src/agents/services/cli-runner.service.ts (增强)

export class CliRunnerService {
  constructor(
    private readonly workspaceSyncService: WorkspaceSyncService
  ) {}

  async streamGenerateWithSync(
    command: string,
    sessionId: string,
    agentId: string,
    machineId: string,
    options: CliRunnerOptions
  ): Promise<AsyncIterable<string>> {
    // 1. 创建本地临时目录
    const localDir = path.join(os.tmpdir(), `workspace-${sessionId}-${Date.now()}`);
    await fs.mkdir(localDir, { recursive: true });

    try {
      // 2. 下载工作区到本地
      await this.workspaceSyncService.downloadWorkspace(sessionId, localDir);

      // 3. 执行CLI命令（在本地目录）
      const result = this.streamGenerate(command, {
        ...options,
        cwd: localDir
      });

      // 4. 执行完成后上传变更
      for await (const chunk of result) {
        yield chunk;
      }

      await this.workspaceSyncService.uploadChanges(
        sessionId,
        localDir,
        agentId,
        machineId
      );
    } finally {
      // 5. 清理本地临时目录
      await fs.rm(localDir, { recursive: true, force: true });
    }
  }
}
```

```typescript
        priority: task.priority || 0,
        attempts: task.maxRetries || 3,
        backoff: {
          type: 'exponential',
          delay: 2000
        }
      }
    );
  }

   * 获取工作区最新版本号（用于一致性检查）

    const latest = await this.workspaceSyncEventRepo.findOne({
      where: { sessionId },
      order: { createdAt: 'DESC' }
    });
    return latest?.id ? 1 : 0;
  }
```

**BullMQ Worker（每台机器运行）**

```typescript
// src/agents/workers/agent-task.worker.ts

import { Processor, WorkerHost } from '@nestjs/bullmq';
import { Job } from 'bullmq';

@Processor('agent-tasks')
export class AgentTaskWorker extends WorkerHost {
  constructor(
    private readonly workspaceSyncService: WorkspaceSyncService,
    private readonly cliRunnerService: CliRunnerService,
    private readonly agentRegistry: AgentRegistryService
  ) {
    super();
  }

  async process(job: Job): Promise<void> {
    const { taskId, sessionId, agentId, taskDescription, workspaceVersion } = job.data;

    // 1. 检查工作区版本一致性
    const currentVersion = await this.workspaceSyncService.getLatestVersion(sessionId);
    if (currentVersion < workspaceVersion) {
      // 等待工作区同步完成
      await this.waitForSync(sessionId, workspaceVersion);
    }

    // 2. 获取Agent配置
    const agent = await this.agentRegistry.getAgent(agentId);

    // 3. 执行任务（自动同步工作区）
    await this.cliRunnerService.streamGenerateWithSync(
      agent.buildCommand(taskDescription),
      sessionId,
      agentId,
      process.env.MACHINE_ID || 'default',
      { timeout: 300000 }
    );
  }

  private async waitForSync(sessionId: string, targetVersion: number): Promise<void> {
    const maxWait = 30000; // 30秒超时
    const interval = 500;
    let elapsed = 0;

    while (elapsed < maxWait) {
      const current = await this.workspaceSyncService.getLatestVersion(sessionId);
      if (current >= targetVersion) return;

      await new Promise(resolve => setTimeout(resolve, interval));
      elapsed += interval;
    }

    throw new Error(`Workspace sync timeout for session ${sessionId}`);
  }
}
```
